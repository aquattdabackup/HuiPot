EXPLANATION OF CBOR DIFFERENCE
-------------------------------
The CBOR suffix is appended by solc AFTER compilation. It encodes an IPFS CID
that points to the compiler metadata JSON (compiler version, source file hashes,
optimizer settings). It is NOT executable — the EVM ignores it; it lives after
the STOP opcode at offset 0 in the deployed code.

The CID differs because the metadata JSON was re-serialised in a fresh build
context (different absolute source paths or different IPFS serialiser run),
even though the source and all settings were identical. This is a known solc
behavior: IPFS CIDs in metadata are not deterministic across build environments
unless cbor-hash=none is set in the compiler settings.

The last four bytes of both CBOR suffixes are 0081c0033:
  - 0x081c = solc version 0.8.28 (8*256+28 = 2076 — matches 0.8.28)
  - 0x0033 = length prefix for the CBOR block (51 bytes)
